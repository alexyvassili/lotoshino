# Lotoshino

Чистый Django-проект с асинхронной главной страницей и запуском через ASGI/Uvicorn.
Python 3.14, язык `ru`, часовой пояс `Europe/Moscow`.
Локальная база — SQLite, серверная — PostgreSQL.

## Локальная разработка

Активируйте окружение `lotoshino`, созданное через `py`:

```bash
source ~/.python3/venvs/lotoshino/bin/activate
make install
make migrate
make run
```

Сайт: <http://127.0.0.1:8000/>, админка: <http://127.0.0.1:8000/admin/>.
Создание администратора:

```bash
poetry run python manage.py createsuperuser
```

`make run` запускает Uvicorn с перезапуском при изменении Python-файлов.
В режиме разработки шаблоны читаются заново при каждом запросе: после правки
HTML достаточно обновить страницу в браузере.
`make run-async` — его псевдоним. Статика админки обслуживается в режиме разработки.
Другой адрес или порт: `make run HOST=127.0.0.1 PORT=8001`.
Автоматическое обновление вкладки браузера не включено.

Зависимости описаны в `pyproject.toml`, точные версии — в `poetry.lock`.
Для обновления в пределах заданных диапазонов: `poetry update`.

## Проверки

```bash
make check       # Ruff, настройки Django и отсутствие пропущенных миграций
make test        # Тесты асинхронной главной страницы
make format     # Форматирование и автоматические исправления Ruff
```

## Настройки сервера

Перед запуском задайте переменные окружения:

- `DJANGO_SETTINGS_MODULE=lotoshino.settings.production`;
- `DJANGO_SECRET_KEY` — отдельный секретный ключ;
- `DJANGO_ALLOWED_HOSTS` — домены через запятую;
- `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_HOST`, `POSTGRES_PORT`.

Файл `.env` автоматически не загружается. Настройки сервера отключают DEBUG,
используют PostgreSQL и требуют HTTPS. Постоянные подключения к БД отключены
(`CONN_MAX_AGE=0`) для ASGI.

```bash
poetry run python manage.py migrate
poetry run python manage.py collectstatic --noinput
poetry run python -m uvicorn lotoshino.asgi:application --host 127.0.0.1 --port 8000
```

Обслуживание `staticfiles/`, `media/`, HTTPS и настройки доверенного reverse proxy
настраиваются при развёртывании под конкретный сервер.

## Редактор статей

В админке раздел «Статьи» использует CKEditor 5 (версия пакета 49.0.0),
размещённый локально в `lotoshino/static/vendor/ckeditor5/49.0.0/`.
Редактор работает в режиме GPL; исходная лицензия — `LICENSE.txt`,
источник и контрольная сумма архива npm — `source.json` в той же папке.
Внешний CDN и облачное хранилище не используются.

Галочка «Опубликовано» включена по умолчанию. После её отключения и сохранения
публичный адрес статьи возвращает 404, сама статья остаётся доступной в админке.
Статус виден в списке статей, где также есть фильтр по публикации.
Существующие статьи при миграции остаются опубликованными.

После сохранения опубликованной статьи админка предупреждает о ссылках на
неопубликованные статьи. При снятии статьи с публикации предупреждение перечисляет
опубликованные статьи, которые на неё ссылаются. Названия ведут на редактирование
соответствующих статей; сохранение не блокируется и сами ссылки не меняются.
Проверяются относительные ссылки и полные URL текущего хоста, включая параметры
и якоря. Внешние сайты не запрашиваются; это не проверка всех отсутствующих страниц.

В карточке статьи перед датой создания расположен список «Ссылки на страницы»:
ссылки из сохранённого текста на главную и статьи сайта. Повторы объединяются,
неопубликованные и отсутствующие статьи помечаются. Ссылки открываются в новой
вкладке; изображения, документы, админка и внешние сайты в список не входят.

При закрытии, обновлении вкладки или переходе со страницы с несохранёнными
изменениями появляется стандартное предупреждение браузера. Учитываются
название, адрес, публикация и содержимое редактора, включая изображения.
Возврат полей к исходным значениям снимает предупреждение; обычное сохранение
проходит без него. Незавершённая загрузка изображения по-прежнему блокирует
сохранение и сохраняет защиту от случайного ухода.

Изображения загружаются кнопкой в редакторе, перетаскиванием либо выбираются
из общей библиотеки. Поддерживаются JPEG, PNG и WebP до 25 мегапикселей.
Максимальные ширина и высота задаются в «Библиотека изображений → Настройки изображений»
(по умолчанию 2560 × 2560 px). Новые изображения вписываются в эти границы
после исправления ориентации, без обрезки и увеличения маленьких исходников.
Изображение можно расположить слева или справа с обтеканием, либо отдельным
блоком по центру; доступны изменение размера, подпись и альтернативный текст.
При ширине экрана до 640 px изображения отображаются отдельными блоками.

Для редакторов, не являющихся суперпользователями, нужны права на добавление
или изменение статей, просмотр изображений и добавление изображений.
Удаление изображений в админке пока отключено, чтобы не ломать ссылки в статьях.

`Article.content` хранит HTML. Форма и обычный `save()` модели очищают его через
nh3; `QuerySet.update()` и `bulk_update()` обходят эту обработку, поэтому их
нельзя использовать для записи необработанного HTML. Загруженные изображения
проверяются Pillow и пересохраняются под случайными именами в `media/images/`.

Статья доступна по `/articles/<slug>/`. Поле «Адрес статьи» необязательно:
если оставить его пустым, при сохранении адрес будет сгенерирован из заголовка
латиницей. Для одинаковых адресов автоматически добавляется числовой суффикс.
Адрес можно задать вручную латинскими буквами, цифрами, дефисами и подчёркиваниями;
он должен быть уникальным.
После сохранения ссылка «Открыть на сайте» ведёт на публичную страницу.
Изменение заголовка сохранённой статьи не меняет её URL. При ручном изменении адреса
старый URL перестаёт работать. Все сохранённые статьи доступны посетителям.
Обтекание и размеры изображений сохраняются на странице благодаря `articles/content.css`.
Главная доступна по `/` и остаётся со статическим содержимым.

## Настройки изображений

В админке рядом с изображениями находится единая форма «Настройки изображений».
Она хранит общие максимальные ширину и высоту изображения и размеры превью и полной версии
для галерей и статей. Для горизонтальных и вертикальных изображений размеры
задаются отдельно как максимальные ширина и высота в пикселях.
Превью не может быть больше полной версии по соответствующей стороне,
а полная версия — больше общего максимума.

Настройки создаются миграцией; добавление второй записи и удаление через админку
отключены. Для редактора нужны отдельные права просмотра/изменения настроек.
Общий максимум применяется сразу при загрузке через редактор и медиабиблиотеку.
Сохраняется основная версия в максимально разрешённых размерах: JPEG и WebP
кодируются с качеством 95, PNG — без потерь. Отдельный исходник сверх общего максимума
не хранится. Маленькие изображения не увеличиваются.
При загрузке в статью или выборе из библиотеки создаются превью и полная версия,
каждая непосредственно из основной версии. Ориентация выбирается автоматически
после учёта EXIF; квадратные изображения используют горизонтальный профиль.
В редактор вставляется превью со ссылкой на полную версию для просмотра.
В панели выбранного изображения есть переключатель «Открывать в полном размере».
По умолчанию он включён: на странице статьи картинка открывается в PhotoViewer
поверх затемнённого фона. При выключении она остаётся обычным превью.
В статьях просмотрщик открывает выбранное изображение без счётчика, миниатюр
и переключения между изображениями (`navigation: false`). В галереях и админке
навигация остаётся доступной. Текстовые ссылки-иллюстрации используют обычный курсор ссылки.
Настройка хранится в HTML каждой вставки (`data-viewer`, `data-full-size`),
не в библиотеке изображений. Ссылка на полную версию сохраняется даже при отключении просмотра.
Изображения в старых статьях без этой настройки используют просмотрщик по умолчанию;
если ссылки на полную версию нет, открывается имеющийся файл.
Кнопка скачивания в PhotoViewer отдаёт основную версию в максимальном сохранённом размере.
На странице статьи сервер определяет исходник по превью из библиотеки, включая старые вставки.
В просмотрщик передаются две ссылки: `href`/`data-src` для показа и `data-download-url`
для скачивания. Исходник загружается только по нажатию кнопки скачивания.
При отсутствии отдельной ссылки скачивается показанная версия. В карточке изображения
скачивание из просмотра любого размера также ведёт на основную версию.
Готовые размеры используются повторно. При изменении настроек новые вставки получают
новые размеры, а прежние файлы и ссылки в статьях сохраняются. В карточке изображения перечислены все готовые версии,
их фактические размеры, ограничения и объём файлов.
Исходник получает имя `UUID.ext`, новые производные — `UUID_ширинаxвысота.ext`,
например `UUID_320x222.jpg`. В имени указаны реальные размеры после уменьшения,
а не ограничения профиля. Одинаковые размеры одного исходника используют общий файл.
Старые файлы со случайными именами не переименовываются. При конфликте с уже занятым
именем хранилище добавляет суффикс, сохраняя существующий файл.
Размеры профилей галереи пока только сохраняются; их генерация ещё не подключена.

В карточке изображения рядом с адресом файла есть кнопка копирования относительного
адреса (`/media/images/…`). В форме ссылки редактора галочка «Иллюстрация» открывает
ссылку в PhotoViewer. Признак хранится в `data-illustration="true"` на ссылке.
Принимаются только адреса этого сайта, начинающиеся с `/`, без домена.
Внешние адреса запрещены в редакторе и форме статьи; очистка HTML модели также удаляет
признак иллюстрации у внешних ссылок. Обычные внешние ссылки разрешены.
Просмотрщик загружает иллюстрации только при открытии, запрещает перенаправления,
проверяет тип ответа и возможность декодирования картинки. Отсутствующий, повреждённый
файл или другой тип содержимого показывается как понятная ошибка внутри просмотрщика.
Проверка выполняется браузером без серверного скачивания внешних файлов.

В списке изображений после предпросмотра и в карточке после имеющихся размеров
показаны ссылки на статьи, где изображение вставлено через `<img>` или ссылку-иллюстрацию.
Учитываются основная версия, все производные размеры и прежние основные версии,
сохранённые в истории производных размеров. Повторы на одной странице объединяются.
Ссылки открывают публичные страницы в новой вкладке. Список строится по текущему
содержимому статей, поэтому изменения текста, названия и адреса отражаются сразу.

## Панель отладки

В режиме разработки подключён Django Debug Toolbar: панель SQL-запросов,
шаблонов, времени обработки и других данных текущего запроса.
Она доступна только вошедшему активному суперпользователю с локального адреса
(`127.0.0.1` или `::1`). Та же проверка защищает служебные адреса `/__debug__/`.
Сначала войдите в админку, затем откройте страницу сайта в том же браузере.
При `DEBUG=False` доступ закрыт; настройки production вообще не подключают
панель и её адреса. Пакет установлен в группе зависимостей `dev`.

## Настройки сайта

В разделе «Сайт → Настройки» задаётся максимальный размер одного загружаемого
файла в МБ (1 МБ = 1024 × 1024 байт), по умолчанию 10 МБ. Это общий лимит
для изображений, документов и других файлов. Он не связан с размерами изображений в пикселях.

Админка и редактор проверяют вес до отправки. На сервере общий обработчик
multipart POST считает байты каждого файла до обработки формами. Файл ровно
на границе разрешён; превышение возвращает HTTP 413, и весь запрос отклоняется
без сохранения файлов. Настройка применяется к следующему запросу без перезапуска.
Для управления нужны отдельные права на настройки сайта.

В ASGI Django буферизует тело запроса до обработки multipart; серверный лимит
не заменяет ограничение тела запроса на reverse proxy. Проверка в браузере
предотвращает отправку слишком большого файла при обычной работе через админку.

В настройках сайта отдельно включаются форматы новых загрузок:
JPEG (.jpg/.jpeg), PNG, WebP и документы DOC, DOCX, ODT, PDF, RTF.
По умолчанию все включены. Отключение формата не меняет существующие файлы
и не мешает редактировать их названия. Заменять уже загруженные изображения и документы
через админку нельзя: поле файла в существующих карточках доступно только для чтения.
Загрузка доступна при добавлении нового объекта.
Фильтры выбора изображений в админке и редакторе учитывают настройки,
окончательное решение всегда принимает сервер.

## Библиотека документов

Раздел «Библиотека документов → Документы» позволяет загружать документы,
искать по названию/имени файла, фильтровать по формату и копировать ссылку скачивания.
Файлы хранятся в `media/documents/` под случайными именами. При скачивании
через `/documents/<id>/download/` возвращается исходное имя и заголовок attachment.
Документы публичны, как изображения. Загрузка требует прав на документы.
Общий лимит размера применяется и к документам. Удаление через админку отключено,
чтобы случайно не повредить опубликованные ссылки.

Расширение сверяется с содержимым, MIME от браузера не считается доказательством:
Pillow распознаёт и декодирует изображения; olefile разбирает OLE и проверяется
поток WordDocument/FIB для DOC; zipfile и defusedxml проверяют признаки Word/ODT
внутри пакета. ZIP не извлекается на диск; XML ограничен 8 МБ, общий объявленный
размер распаковки — 64 МБ, количество записей — 4096. Для PDF проверяются заголовок
и завершающая сигнатура, для RTF — заголовок RTF и завершение документа.
Это проверка принадлежности формату, а не полная проверка корректности документа.
Файлы DOCX с макросами и зашифрованные DOC/DOCX/ODT не поддерживаются.

## Подборки статей

«Подборки статей» в админке создают страницы с выбранными статьями, например
`/history/`. У подборки есть название, уникальная часть адреса (`history`),
необязательный вступительный текст и флаг «Опубликовано» (включён по умолчанию).
Служебные адреса использовать нельзя; адрес без завершающего слеша перенаправляется
на вариант со слешем. Неопубликованная подборка возвращает 404.

Статьи выбираются поиском. Для каждой задаются название анонса (автоматически
подставляется из статьи, но редактируется независимо), необязательное изображение,
аннотация и текст ссылки — по умолчанию «Читать далее». Порядок меняется кнопками
«Выше»/«Ниже» и сохраняется вместе с подборкой. Одну статью нельзя добавить дважды.
Удаление элемента подборки не удаляет статью. Неопубликованные статьи остаются
в составе подборки в админке, но на публичной странице скрываются.

Выбор изображения по умолчанию показывает встроенные изображения выбранной статьи
(`img`, включая производные размеры), без текстовых ссылок-иллюстраций.
Можно переключиться на всю библиотеку, искать по названию/описанию или загрузить
новое изображение. Загрузка использует общие ограничения размера и форматов,
проверку содержимого и создание размеров для статей. Анонс использует превью из
настроек статей. Изображение и заголовок анонса ведут на статью.
Использование изображений в подборках отображается в медиабиблиотеке; ссылки
из статей на подборки отображаются в списке ссылок страницы редактирования статьи.
